# 0077. The screenshot matrix, test only Devanagari fixtures, and the translation workflow

Date: 2026-10-05
Status: Proposed (draft in the Phase 3 planning pull request; revisable until that pull request is merged)

Decided by Claude (technical review) in the Phase 3 planning prompt (D5, D9). The file format, the fixture mechanism and the recording rule are the planning session's, for review.

## Decision

1. **The matrix is three locales (en, hi, mr) by three font scales (100, 150 and 200 percent): nine combinations, run on every screen state once, in Light.** Appearances differ in colour only, so each screen state is also captured in Dark and in each of the five Pastel palettes at English 100 percent. Palette coverage beyond that is `ContrastTest`'s (ADR 0075).
2. **Comparison is strict** (`changeThreshold = 0`). Captures are of settled states, with the Compose test clock paused and advanced past any indication animation. **Only goldens rendered by Linux CI are committed.** The implementing machine is Windows, with no usable WSL2 toolchain or Docker, so the route is the CI job itself: `android-screenshots` runs on every pull request, verifies the committed goldens, then records what the commit renders and uploads it as the artifact `goldens` (and the comparison images as `screenshot-diff` when verify failed), and fails if verify failed. A new or deliberately changed screen therefore turns the job red once; the implementer downloads the artifact through the GitHub MCP, looks at each changed image, commits the files unchanged and pushes, and the job goes green. A golden that changed without being meant to is a regression to fix in code. The route was proved on a throwaway draft pull request, #27, closed unmerged (plan section 2): a Windows recorded golden verified on Linux and was byte identical to the Linux recording for that one capture, a changed screen failed the job, and the downloaded Linux golden passed it. A manually dispatched recording workflow was the first draft's route and is dropped: a workflow can be dispatched only once it is on the default branch, and the job needs nothing more.
3. **Nothing is machine translated.** Shubham's brother supplies and reviews the Hindi and Marathi strings. English is frozen in two waves: wave 1 is every string Phase 2 shipped, exported as soon as the pipeline exists; wave 2 is every Phase 3 string, exported when the last screen's pull request merges. The export is one UTF-8 CSV that a spreadsheet opens (`key, kind, quantity, health_adjacent, note, en, hi, mr`), written by `scripts/strings/ExportStrings.java`. `ImportStrings.java` writes `values-hi` and `values-mr` from it, and refuses a row whose placeholders differ from the English or whose plural quantities are not the locale's.
4. **Until his strings exist, tests in hi and mr use fixture strings**: Devanagari text about 30 percent longer than the English, dense in matras and conjuncts, each beginning with a fixture marker, generated from the English by `scripts/strings/GenerateFixtures.java`. They are real resources, so that every surface that reads a resource can be tested (a notification, a channel name, the widget), but they live where no user can meet them: in the **debug source set only**, under the locale qualifiers `hi-rXA` and `mr-rXA`, a region no device is set to. Tests ask for those locales; a phone set to Hindi resolves `values-hi`, which does not exist until his strings are imported, and so shows English. They are never a shipped resource: `NoFixtureInResourcesTest` fails if any string in `values-hi` or `values-mr` contains the fixture marker or if the main source set holds an `rXA` folder, `verifyNoDebugComponents`' sibling check `verifyNoFixtureResources` fails if the merged release resources contain an `rXA` configuration, and both fail closed if they find no fixture at all in the debug source set.
5. **When his strings are imported, the hi and mr goldens are recorded again from the real resources.** The fixture path stays for strings added later. The human review exit criterion is recorded in `MANUAL_CHECKS.md` with the reviewer, the date and the commit reviewed.

## Alternatives considered

- **Placeholder Hindi in `values-hi`.** Rejected: it would ship.
- **XLIFF.** Rejected: he works in a spreadsheet.
