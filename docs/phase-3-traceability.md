# Phase 3 traceability

Status: a scaffold written by the Phase 3 planning session, filled in as pull requests land. PR 1 (`phase-3/schema-v6`) has filled rows A11 and A19, its part of A23, and the section "PR 1: shared schema version 6" below. PR 2 (`phase-3/occurrence-criticality`) has filled rows A10 and its part of A24, and the section "PR 2: criticality from the occurrence, and Gentle does not ring". No other row has evidence yet. Every row's test and mutation come from `docs/phase-3-plan.md`; the pull request that delivers a row fills in the observed failure and the two SHAs, and changes the status. "Merged at" is filled by the pull request after the merge, since a pull request cannot name its own merge commit.

Columns, as in `phase-2-traceability.md`: **ID**; **Requirement** and its source; **PR**; **Test** (class and method, as named in the plan); **Mutation planned** (the change that must make the test fail); **Observed failure** (the test that failed and its message, filled in when run); **Mutated at** (the SHA the mutation was run on); **Merged at** (the merge commit); **Status** (`PLANNED`, then `PASS`, or `DEFERRED` with an owner); **Device remainder** (a `MANUAL_CHECKS.md` row).

A mutation is recorded only after its diff was shown and was exactly the intended change, and after the intended test failed on an assertion for the intended reason (`CLAUDE.md`, mutation hygiene). A compile error counts only where the plan says it is the intended result.
